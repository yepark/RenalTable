# RenalTable 제품 요구사항(PRD)

- 상태: Phase 0 초안
- 기준일: 2026-11-01
- 제품 슬로건: **Eat Well, Care Better.**
- 대상 릴리스: 공개 가능한 한국어 MVP

## 1. 문제와 목표

신장 질환 환자의 식사는 질환 단계, 투석 방식, 검사 결과, 동반 질환과 의료진 지시에 따라 달라진다. 일반적인 음식 목록만으로는 개인에게 적절한 식사 계획을 세우기 어렵고, 반대로 단순한 “먹어도 되는 음식” 표시는 위험한 확신을 줄 수 있다.

RenalTable의 목표는 신뢰할 수 있는 출처의 식품 정보를 이해하기 쉽게 보여주고, 사용자가 의료진에게 받은 목표를 직접 입력했을 때만 그 목표와 식단을 수학적으로 비교하도록 돕는 것이다. 서비스는 진단·처방·의료 상담을 대체하지 않는다.

서비스는 모든 사용자에게 무료로 제공한다. MVP의 인프라 운영비도 월 0원을 목표로 하며 광고, 결제, 유료 전환 기능을 넣지 않는다. 무료 제공자의 한도를 넘으면 자동 과금으로 전환하지 않고 기능 축소, 캐시 최적화 또는 배포 일시 중지를 선택한다.

## 2. 성공 기준

### 제품 성공

- 회원가입 없이 모바일에서 음식 검색, 프로필 설정, 레시피 확인, 7일 식단 작성, 장보기 목록 생성을 완료할 수 있다.
- 프로필과 식단표가 브라우저 새로고침 뒤에도 유지된다.
- 모든 영양 표시에서 기준량, 단위, 출처, 갱신일, 누락 여부를 확인할 수 있다.
- 목표 미입력 또는 데이터 불완전 시 적합 여부를 판정하지 않는다.

### 품질 성공

- 핵심 흐름 E2E가 Chromium, WebKit, Firefox에서 통과한다.
- WCAG 2.2 AA를 목표로 자동 검사와 키보드 수동 검사를 통과한다.
- 공개 페이지의 의료 문구와 레시피는 검토 상태와 출처를 가진다.
- Core Web Vitals와 성능 예산은 Phase 1 기준선 측정 후 확정한다.

### MVP에서 측정하지 않는 것

의학적 효과, 질병 개선, 검사 수치 개선은 MVP 성공 지표가 아니다. 임상적 효능을 주장하지 않는다.

## 3. 사용자와 핵심 과업

| 사용자 | 핵심 과업 |
| --- | --- |
| 신장 질환 환자 | 음식의 영양정보 확인, 의료진이 준 목표와 섭취량 비교, 식단 구성 |
| 보호자 | 한국 가정식 레시피 탐색, 주간 식단 작성, 장보기 목록 생성 |

성인 사용자를 MVP의 주 대상으로 가정한다. 소아, 임신, 이식 환자에 대한 특화 추천은 범위 밖이며 해당 조건에는 전문가 상담 안내를 우선한다.

## 4. MVP 범위와 수용 기준

### `/` 홈

- 브랜드, 소개, 검색, 프로필·레시피·식단표·가이드 진입점을 제공한다.
- 모든 페이지에서 의료 상담 대체 불가 안내에 접근할 수 있다.
- 추천 영역은 “모든 환자에게 안전”이 아니라 검토된 레시피 탐색 영역으로 표현한다.

### `/profile` 식단 조건 설정

- 상태를 `미설정 / 비투석 / 혈액투석 / 복막투석`으로 구분한다.
- 간편 설정은 치료 방식, 알레르기, 제외 식재료를 받는다.
- 상세 설정은 나트륨·칼륨·인·단백질과 선택적 수분 목표를 받는다.
- 목표는 값, 단위, 기간(일), 입력 출처(의료진 안내), 갱신일을 포함한다.
- 데이터는 버전이 있는 브라우저 저장소에만 저장하며 전체 삭제 기능을 제공한다.

### `/foods` 음식 검색

- 이름과 카테고리로 검색하고 100 g 및 사용자 입력 섭취량 기준을 비교한다.
- 열량, 단백질, 나트륨, 칼륨, 인을 표시한다.
- 값이 없으면 `정보 없음`으로 표시하고 합계·평가에서 누락을 전파한다.
- 식품 상세에서 원 출처, 기준량, 데이터 생성일/갱신일을 표시한다.

### `/meals`, `/meals/[id]` 레시피

- 식사 유형, 난이도, 시간으로 검토 완료 레시피를 찾는다.
- 1인분 재료, 단계별 조리법, 알레르기, 주의, 출처, 검토 상태를 표시한다.
- 영양값은 식품 데이터와 재료량으로 계산하고 계산 버전과 완전성을 표시한다.
- 검토 전 레시피는 공개 목록에 나타나지 않는다.

### `/planner` 주간 식단과 장보기 목록

- 7일 × 아침·점심·저녁에 메뉴를 추가·교체·삭제한다.
- 일별 영양 합계를 계산하되 일부 값 누락 시 `부분 합계`로 표시한다.
- 사용자가 입력한 목표가 있을 때만 수치 차이를 보여준다.
- 같은 메뉴 반복 빈도를 보여주되 의료적 적합성과 혼동하지 않는다.
- 재료를 정규화된 식재료 ID와 단위 기준으로 합산하고, 변환할 수 없는 단위는 별도 항목으로 남긴다.
- 체크 상태, 인쇄 화면, Web Share API 지원 환경의 공유를 제공한다. 공유 미지원 시 복사/인쇄 대안을 제공한다.

### `/guide` 건강 정보

- 나트륨, 칼륨, 인, 단백질, 투석 여부, 영양표 읽기, 상담 필요 상황을 다룬다.
- 각 글에 출처, 최종 검토일, 검토 상태를 표시한다.
- 의료 전문가 검토 전 콘텐츠는 공개하지 않는다.

## 5. 비기능 요구사항

- **안전성:** `docs/NUTRITION_RULES.md`의 보류 우선 규칙을 따른다.
- **개인정보:** 계정과 서버 건강 프로필 저장을 제외한다. 자세한 정책은 `docs/SECURITY.md`에 둔다.
- **접근성:** WCAG 2.2 AA, 4.5:1 본문 대비, 키보드 운용, 200% 확대, 24×24 CSS px 이상의 포인터 목표를 주요 기준으로 한다.
- **반응형:** 320 px 폭부터 지원하며 모바일 우선으로 설계한다.
- **성능:** 서버 컴포넌트와 정적 콘텐츠를 우선하고 클라이언트 JavaScript를 최소화한다.
- **지역화:** 사용자 UI와 오류는 한국어, 수치 형식은 `ko-KR`, 단위는 값과 분리해 읽을 수 있게 표시한다.
- **관찰 가능성:** 건강 프로필·검색어를 로그나 분석 도구에 보내지 않는다. 운영 로그는 오류 진단에 필요한 최소 메타데이터만 수집한다.
- **비용:** 사용자 이용료와 초기 월 인프라 비용 모두 0원을 목표로 한다. 결제수단 등록이나 초과 사용 자동 과금이 필요한 서비스는 별도 승인 없이는 도입하지 않는다.

## 6. MVP 제외 범위

- 회원가입, 클라우드 프로필 동기화, 광고, 결제
- AI가 자동 생성한 레시피/영양값의 공개
- 검사 결과 해석, 진단, 약물 조언, 자동 영양 처방
- 의료진용 대시보드와 관리자 CMS 전체 구현
- 네이티브 앱, 푸시 알림, 오프라인 완전 지원
- 소아·임신·이식 환자 특화 추천

## 7. 의료 안전 승인 게이트

다음은 구현 완료와 별개로 사람의 명시적 승인이 필요하다.

1. 신장내과 전문의 또는 신장 전문 임상영양사의 콘텐츠·표현 검토
2. 운영 식품 데이터의 출처·라이선스·필드 매핑 검증
3. 공개 배포 전 개인정보·접근성·보안 검토

## 8. 미검증 가정

- 공공데이터의 칼륨·인 값은 모든 식품에 존재하지 않는다.
- 음식명 중복과 조리 상태 차이는 단일 이름 병합으로 해결할 수 없다.
- 브라우저 저장만으로 초기 사용성은 충족하지만 기기 간 이동 요구가 생길 수 있다.
- 공개 무료 서비스가 Vercel Hobby의 개인·비상업 조건을 만족하는지는 배포 전 계정/운영 주체 기준으로 재확인해야 한다.
