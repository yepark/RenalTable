# 영양 계산 및 안전성 규칙

- 상태: Phase 0 안전 규격
- 공개 전 승인: 신장내과 전문의 또는 신장 전문 임상영양사 검토 필요

## 1. 제품이 하는 일과 하지 않는 일

RenalTable은 출처가 있는 영양값을 환산·합산하고, 사용자가 직접 입력한 의료진 안내 목표와 비교한다. 진단, 처방, 검사 결과 해석, 개인 목표 생성은 하지 않는다.

KDIGO 2024는 CKD 식이를 개인 상태와 영양 상태에 맞춰 다뤄야 함을 강조하며, 단백질 제한은 영양실조·근감소 등과 충돌할 수 있다. KDOQI 2020 역시 CKD 전 단계와 이식 환자를 포함한 전문적 영양 평가를 다룬다. 따라서 지침의 일반 수치를 앱 기본 목표로 자동 적용하지 않는다.

근거:

- [KDIGO 2024 CKD Guideline](https://kdigo.org/guidelines/ckd-evaluation-and-management/)
- [KDIGO 2024 Executive Summary](https://kdigo.org/wp-content/uploads/2017/02/KDIGO-2024-CKD-Guideline-Executive-Summary.pdf)
- [KDOQI 2020 Nutrition in CKD](https://www.kidney.org/professionals/kdoqi-guidelines)
- [대한신장학회 일반인 교육 자료](https://ksn.or.kr/general/vod/ckd.php)

## 2. 상태 모델

### 치료 방식

- `UNSET`: 사용자가 선택하지 않음
- `NON_DIALYSIS`: 비투석
- `HEMODIALYSIS`: 혈액투석
- `PERITONEAL_DIALYSIS`: 복막투석

이 값은 어떤 기본 목표도 생성하지 않는다. 추천 이유와 주의 문구 분기에만 사용하며, 전문가가 승인한 규칙만 활성화한다.

### 데이터 완전성

- `COMPLETE`: 계산에 필요한 모든 항목이 출처 있는 값 보유
- `PARTIAL`: 알려진 소계가 있으나 하나 이상 누락
- `MISSING`: 유효한 값이 없음
- `NOT_COMPARABLE`: 단위/기준량을 안전하게 변환할 수 없음

## 3. 환산과 합산

질량 기준 값의 기본 식:

```text
섭취 영양량 = 기준 영양량 × 섭취 가능 중량(g) ÷ 기준 중량(g)
```

- 계산 내부는 decimal 정밀도를 사용한다.
- 반올림은 표시 단계에서 영양소별 규칙으로 한 번만 한다.
- `TRACE`나 `BELOW_LIMIT`는 임의 숫자로 치환하지 않는다.
- 부피↔질량 변환은 해당 식재료와 단위에 대한 검증된 변환 계수가 있을 때만 한다.
- 조리 전후 중량, 폐기율, 수율, 영양 보존율은 근거와 버전이 있을 때만 적용한다.

레시피 영양량은 각 재료 환산값의 합이다. 한 영양소라도 필수 재료 값이 빠지면 알려진 값은 `부분 합계`로 표시할 수 있지만 완전한 합계나 목표 충족으로 판정하지 않는다.

## 4. 목표 비교

비교 전 조건:

1. 사용자가 해당 영양소 목표를 직접 입력했다.
2. 목표 단위와 기간을 표준 단위로 변환할 수 있다.
3. 대상 식사/하루 합계가 `COMPLETE`다.
4. 알레르기·제외 식재료 충돌이 없다.

결과:

- `NO_TARGET`: 목표 없음, 일반 정보만 표시
- `INCOMPLETE_DATA`: 데이터 누락, 판단 보류
- `CONFLICT`: 목표 범위 자체 또는 조건 충돌, 확인 요청
- `WITHIN_USER_TARGET`: 입력한 수치 범위 안; 의료적 안전을 의미하지 않음
- `ABOVE_USER_TARGET` / `BELOW_USER_TARGET`: 수치 차이 표시
- `EXCLUDED`: 알레르기 또는 제외 재료 포함

사용자 문구는 `입력한 하루 목표의 35%예요`처럼 수학적 사실을 설명한다. `적합`, `안전`, `권장 처방`으로 표현하지 않는다.

## 5. 알레르기와 제외 규칙

- 알레르기는 영양 점수보다 먼저 적용하는 hard exclusion이다.
- `포함할 수 있음`, 교차오염, 원재료 미상은 자동 안전 판정하지 않는다.
- 문자열 포함 검색만으로 알레르기를 판정하지 않고 정규화된 allergen/ingredient ID와 검토된 매핑을 사용한다.
- 사용자의 일반 제외 식재료와 기호는 별도 조건으로 두며 알레르기와 같은 의료 표현을 쓰지 않는다.

## 6. 추천 정렬

순수 함수 입력: 공개 레시피, 완전성, 사용자 목표, 치료 방식, 알레르기/제외, 최근 식단.

1. 미게시/검토 만료 레시피 제외
2. 알레르기·제외 식재료 충돌 제외
3. 필수 영양 데이터 불완전 후보는 목표 기반 추천에서 제외하고 일반 탐색에만 표시
4. 목표가 없으면 의료 점수를 만들지 않고 검색 관련성·다양성·조리 조건으로 정렬
5. 목표가 있으면 각 수치의 차이를 결정적으로 계산
6. 동점은 반복 빈도, 조리 시간, 안정적인 ID 순으로 정렬

추천 이유는 템플릿으로 생성하고 계산 버전을 기록한다.

## 7. 충돌과 보류

- 최소 단백질과 최대 단백질이 역전되는 등 목표가 모순이면 저장 전 오류를 알린다.
- 서로 다른 시점의 의료진 목표를 자동 병합하지 않는다.
- 투석 방식 변경 시 기존 목표를 유지하되 `다시 확인 필요`로 표시한다.
- 목표 갱신일이 오래됐다고 자동 만료시키지 않으며, 재확인 알림 기준은 전문가 검토 후 정한다.
- 탈수, 부종, 고칼륨혈증 등 임상 상황을 앱이 추론하지 않는다.

## 8. 테스트 불변조건

- 누락값을 포함한 합계는 `COMPLETE`가 될 수 없다.
- 0은 `PRESENT`인 원자료 0에서만 나온다.
- 인분을 2배 하면 선형 계산 대상 영양량은 정확히 2배가 된다.
- 단위 변환 왕복 오차가 정한 허용범위를 넘으면 계산을 보류한다.
- 알레르기 충돌 레시피는 영양 점수가 좋아도 후보가 될 수 없다.
- 목표가 없으면 `WITHIN_USER_TARGET`이 나올 수 없다.
- 모든 결과가 동일 입력과 계산 버전에서 결정적이다.

## 9. 전문가 검토 필요

- 치료 방식별 안내 문구
- 칼륨·인·수분 관련 건강 가이드
- 조리법에 따른 영양 변화 적용 여부
- 알레르기 매핑과 교차오염 표현
- 콘텐츠 검토 유효기간과 재검토 기준
